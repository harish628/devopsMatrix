DevOpsMatrix CI/CD User Guide

Set up GitHub Actions → Amazon ECR → Amazon EKS from scratch. Written for new team members. Region: ap-south-1.

Prerequisites

  • GitHub repo with admin access; AWS account with permission to create IAM roles, ECR and EKS resources
  • An existing EKS cluster (eksCluster) and the AWS CLI configured locally for one-time setup
  • kubectl installed locally; a Dockerfile in the repo root

2One-time AWS setup

2.1 Create the GitHub OIDC provider

AWS Console → IAM → Identity providers → Add provider → OpenID Connect. Provider URL https://token.actions.githubusercontent.com, audience sts.amazonaws.com.

2.2 Create the IAM role githubactionsRole

Trust policy (replace the placeholders):

{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": {"Federated": "arn:aws:iam::<ACCOUNT_ID>:oidc-provider/token.actions.githubusercontent.com"},
    "Action": "sts:AssumeRoleWithWebIdentity",
    "Condition": {
      "StringEquals": {"token.actions.githubusercontent.com:aud": "sts.amazonaws.com"},
      "StringLike":   {"token.actions.githubusercontent.com:sub": "repo:<ORG>/<REPO>:ref:refs/heads/main"}
    }
  }]
}

Attach permissions: ECR push/pull (for example AmazonEC2ContainerRegistryPowerUser) plus eks:DescribeCluster.

2.3 Give the role access to the cluster

aws eks create-access-entry --cluster-name eksCluster --region ap-south-1 \
  --principal-arn arn:aws:iam::<ACCOUNT_ID>:role/githubactionsRole

aws eks associate-access-policy --cluster-name eksCluster --region ap-south-1 \
  --principal-arn arn:aws:iam::<ACCOUNT_ID>:role/githubactionsRole \
  --policy-arn arn:aws:eks::aws:cluster-access-policy/AmazonEKSClusterAdminPolicy \
  --access-scope type=cluster
Without this step, CD fails at kubectl get nodes with "You must be logged in to the server (Unauthorized)".

3Kubernetes manifests

The container name in deployment.yaml must be nginx, because CD runs kubectl set image ... nginx=....

# namespace.yaml
apiVersion: v1
kind: Namespace
metadata: {name: static-site}
---
# deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata: {name: static-site, namespace: static-site}
spec:
  replicas: 2
  selector: {matchLabels: {app: static-site}}
  template:
    metadata: {labels: {app: static-site}}
    spec:
      containers:
        - name: nginx
          image: nginx:stable   # replaced by CD with the ECR image
          ports: [{containerPort: 80}]
---
# service.yaml
apiVersion: v1
kind: Service
metadata: {name: static-site, namespace: static-site}
spec:
  type: LoadBalancer
  selector: {app: static-site}
  ports: [{port: 80, targetPort: 80}]

(Each document goes in its own file.)

4CI workflow – .github/workflows/ci.yaml

Builds the image, tags it with the commit SHA and pushes it to ECR.

name: DevOpsMatrix CI

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  id-token: write
  contents: read

env:
  AWS_REGION: ap-south-1
  ECR_REPOSITORY: static-site

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::<ACCOUNT_ID>:role/githubactionsRole
          aws-region: ${{ env.AWS_REGION }}

      - name: Get account ID and ECR registry
        run: |
          ID=$(aws sts get-caller-identity --query Account --output text)
          echo "REGISTRY=$ID.dkr.ecr.$AWS_REGION.amazonaws.com" >> "$GITHUB_ENV"

      - name: Create ECR repository if missing
        run: |
          aws ecr describe-repositories --repository-names "$ECR_REPOSITORY" --region "$AWS_REGION" >/dev/null 2>&1 \
          || aws ecr create-repository --repository-name "$ECR_REPOSITORY" --region "$AWS_REGION"

      - name: Login to ECR
        run: |
          aws ecr get-login-password --region "$AWS_REGION" |
          docker login --username AWS --password-stdin "$REGISTRY"

      - name: Build and push image
        run: |
          docker build -t "$REGISTRY/$ECR_REPOSITORY:${GITHUB_SHA}" .
          docker push "$REGISTRY/$ECR_REPOSITORY:${GITHUB_SHA}"

      - name: Verify image in ECR
        run: |
          aws ecr describe-images --repository-name "$ECR_REPOSITORY" \
            --image-ids imageTag="${GITHUB_SHA}" --region "$AWS_REGION"

5CD workflow – .github/workflows/cd.yaml

Starts automatically when CI succeeds and deploys the exact commit CI built.

name: DevOpsMatrix CD

on:
  workflow_run:
    workflows: ["DevOpsMatrix CI"]
    types: [completed]

permissions:
  id-token: write
  contents: read

env:
  AWS_REGION: ap-south-1
  EKS_CLUSTER_NAME: eksCluster
  ECR_REPOSITORY: static-site
  K8S_NAMESPACE: static-site
  DEPLOYMENT_NAME: static-site

jobs:
  deploy:
    if: ${{ github.event.workflow_run.conclusion == 'success' && github.event.workflow_run.head_branch == 'main' }}
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          ref: ${{ github.event.workflow_run.head_sha }}

      - name: Configure AWS credentials
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: arn:aws:iam::<ACCOUNT_ID>:role/githubactionsRole
          aws-region: ${{ env.AWS_REGION }}

      - name: Connect to EKS
        run: |
          aws eks update-kubeconfig --region "$AWS_REGION" --name "$EKS_CLUSTER_NAME"
          kubectl get nodes

      - name: Set image URI and verify it exists
        run: |
          ID=$(aws sts get-caller-identity --query Account --output text)
          SHA=${{ github.event.workflow_run.head_sha }}
          echo "IMAGE_URI=$ID.dkr.ecr.$AWS_REGION.amazonaws.com/$ECR_REPOSITORY:$SHA" >> "$GITHUB_ENV"
          aws ecr describe-images --repository-name "$ECR_REPOSITORY" \
            --image-ids imageTag="$SHA" --region "$AWS_REGION"

      - name: Apply manifests
        run: |
          kubectl apply -f EKS/kubernetes/namespace.yaml
          kubectl apply -f EKS/kubernetes/deployment.yaml
          kubectl apply -f EKS/kubernetes/service.yaml

      - name: Update image and wait for rollout
        run: |
          kubectl set image deployment/$DEPLOYMENT_NAME nginx="$IMAGE_URI" -n "$K8S_NAMESPACE"
          kubectl rollout status deployment/$DEPLOYMENT_NAME -n "$K8S_NAMESPACE" --timeout=180s

      - name: Verify
        run: kubectl get deployment,pods,service -n "$K8S_NAMESPACE"
Important: workflow_run workflows only run from the default branch, so cd.yaml must be merged into main before it will trigger.

git commit -m "Add CI/CD pipelines"
git push origin main

Open GitHub repo → Actions. You should see CI start first, then CD start on its own once CI is green:

Troubleshooting

SymptomLikely cause and fix
"DevOpsMatrix CI" missing in ActionsWorkflow file not on main, or name: inside the file is wrong. Check each file's name: line.
Not authorized to perform sts:AssumeRoleWithWebIdentityTrust policy sub doesn't match repo/branch, or id-token: write permission is missing.
CD never startscd.yaml isn't on main, or the CI workflow name in workflows: doesn't match exactly.
kubectl get nodes UnauthorizedCreate the EKS access entry for the role (step 2.3).
Image not found in ECRCI failed or pushed a different SHA. Check CI logs for the push step.
Rollout times outPod can't pull the image (ECR permissions on the node role) or the container crashes. Run kubectl describe pod and kubectl logs.
set image fails: container not foundContainer name in deployment.yaml isn't nginx.
